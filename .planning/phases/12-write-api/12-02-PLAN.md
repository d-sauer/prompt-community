  <files>src/workers/api/routes/prompts.ts</files>
  <behavior>
    PATCH /:id:
    - No JWT → 401
    - Non-author AND non-maintainer → 403
    - Author can update: title, body, category, model, difficulty, tags, status ('draft'/'published' only)
    - Non-maintainer attempting status 'flagged' or 'hidden' → 403
    - Unknown prompt ID → 404
    - Returns 200 with updated prompt object

    DELETE /:id:
    - No JWT → 401
    - Not author AND not maintainer → 403
    - Unknown prompt ID → 404
    - On success: delete in FK dependency order:
      1. notifications WHERE prompt_id=id
      2. reactions WHERE prompt_id=id
      3. bookmarks WHERE prompt_id=id
      4. comments WHERE prompt_id=id
      5. prompt_tags WHERE prompt_id=id
      6. prompt_versions WHERE prompt_id=id
      7. prompts WHERE id=id
      (Note: moderation_log rows are KEPT — audit trail preserved even after prompt deletion)
    - Returns 204 No Content
  </behavior>
  <action>
    Append `app.patch('/:id', requireAuth(), ...)` and `app.delete('/:id', requireAuth(), ...)` to `src/workers/api/routes/prompts.ts`.

    PATCH handler:
    1. Load prompt by id — 404 if not found
    2. Check auth: if user.id !== prompt.author_id AND user.role !== 'maintainer' → 403
    3. Parse partial body
    4. If status provided and is 'flagged' or 'hidden' and user.role !== 'maintainer' → 403
    5. Build update object from allowed fields (only include fields that are present in body)
    6. Update prompts table with `db.update(schema.prompts).set({...updates, updated_at: sql\`(strftime('%Y-%m-%dT%H:%M:%fZ', 'now'))\`}).where(eq(schema.prompts.id, id))`
    7. If tags in body: delete existing prompt_tags for this prompt, bulk insert new ones
    8. Return 200 with the full updated prompt object (re-fetch tags after update)

    DELETE handler:
    1. Load prompt by id — 404 if not found
    2. Check auth: if user.id !== prompt.author_id AND user.role !== 'maintainer' → 403
    3. Delete in dependency order using Drizzle delete (see behavior section)
    4. Wrap in a D1 batch or sequential awaits (D1 does not support transactions in the same way — use sequential deletes)
    5. Return 204 with no body: `return new Response(null, { status: 204 })`

    Import `sql` from 'drizzle-orm' for the updated_at timestamp.
